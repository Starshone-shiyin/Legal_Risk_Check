# 版本报告素材模板

后续每次发布新版本时，必须同步更新 `changelog.md`，并在 `docs/final_report_version_guide.md` 中按以下格式补充一节；若路线或质量门禁变化，还要同步更新 `docs/project_review_and_roadmap.md`。

发布清单：
- 版本号同步：应用入口、changelog、相关 docs 保持一致。
- 变更记录：说明目标、实现、兼容性影响和 fallback 行为。
- 文档同步：更新最终报告素材、路线图或质量门禁说明。
- 质量验证：记录实际运行过的命令；未运行的评测必须明确说明原因。

## vX.Y.Z：版本标题

阶段定位：一句话说明本版本处于系统演进的哪个阶段。

解决的问题：说明本版本针对的痛点，尽量使用业务或法律风控语言，而不是只写技术实现。

关键实现：
- 实现点 1。
- 实现点 2。
- 实现点 3。

报告写法：
> 用一段可以直接放进最终报告的正式表述，说明本版本的价值。

验证方式：
- 运行过哪些单元测试。
- 运行过哪些 RAG/Risk/Report 评测。
- 当前通过率或关键验证结论。

后续影响：
- 本版本为下一阶段提供了什么基础。
- 是否引入新的注意事项或技术债。

## 示例

### v0.3.5：法规清单与增量评测

阶段定位：支撑知识库扩容的测试效率优化阶段。

解决的问题：随着法规数量增加，每次新增或修改法规后都运行全量评测成本过高，需要按受影响范围进行增量验证。

关键实现：
- 新增法规 manifest，记录文档元数据、领域、关键锚点和 smoke case。
- 新增 impact eval 工具，支持按法规、领域或分类运行相关评测。
- 新增 smoke case 格式，用于快速验证新法规是否可检索、可引用、可回答。

报告写法：
> v0.3.5 建立了法规扩容场景下的增量评测机制，使系统能够在新增单部法规或单个领域规则时，仅运行相关测试集，降低回归成本，同时保留版本发布前的全量质量门禁。

验证方式：
- 单元测试通过。
- 指定 source 的 smoke eval 通过。
- 全量 RAG/Risk/Report 评测在版本发布前通过。

后续影响：
- 支撑大规模法规库扩容。
- 为领域路由和知识覆盖率统计提供数据基础。
