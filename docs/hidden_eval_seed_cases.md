# Hidden Eval Seed Cases

本文档记录真实用户手工测试中发现的复杂企业法律场景。这里的样本暂不进入公开 RAG Eval，也不直接用于补规则；用途是作为后续 hidden eval / 企业场景层的种子样本，观察系统在复杂事实、争点识别、证据链和法言法语输出上的泛化能力。

## seed_001_pipl_facial_attendance_complex

### 原始问题

```json
{
  "question": "某科技公司为提升办公安全与访客管理效率，在总部园区上线人脸识别门禁系统。公司已在员工入职时签署《园区安全与信息处理告知书》，明确告知人脸信息用途为身份核验与门禁管理，存储期限为离职后30日删除，并取得员工书面同意。系统数据加密存储，仅行政与安保部门可访问，公司未向第三方出售或共享数据。但员工若拒绝录入人脸，则需每天到前台人工登记后进入园区，平均耗时15分钟。部分员工认为该替代方案实际不可行。公司未进行个人信息保护影响评估，也无法证明必须使用人脸识别，仅表示效率更高。请问该做法是否存在法律风险？",
  "k": 5
}
```

### 期望争点

- `biometric_sensitive_info`：人脸信息/生物识别信息属于敏感个人信息。
- `notice_and_separate_consent`：已告知并书面同意，但员工场景下仍需审查同意自愿性、充分知情和单独同意。
- `necessity_and_proportionality`：效率更高不当然等于处理敏感个人信息的必要性。
- `alternative_method_burden`：每天人工登记约 15 分钟，可能使替代方案缺乏真实可选择性。
- `pipia_required`：处理敏感个人信息前应开展个人信息保护影响评估。
- `access_and_security_measures`：加密存储、权限控制、未共享数据属于降低风险因素，但不能替代必要性、影响评估和自愿性要求。

### 期望核心法条

- 《中华人民共和国个人信息保护法》第6条：最小必要、限于实现处理目的的最小范围。
- 《中华人民共和国个人信息保护法》第16条：不得因个人不同意处理其个人信息而拒绝提供产品或者服务，处理非必要个人信息除外。
- 《中华人民共和国个人信息保护法》第17条：处理个人信息前的告知义务。
- 《中华人民共和国个人信息保护法》第28条：敏感个人信息定义。
- 《中华人民共和国个人信息保护法》第29条：处理敏感个人信息应取得个人的单独同意。
- 《中华人民共和国个人信息保护法》第30条：处理敏感个人信息还应告知必要性和对个人权益的影响。
- 《中华人民共和国个人信息保护法》第55条：处理敏感个人信息前应进行个人信息保护影响评估。
- 《中华人民共和国个人信息保护法》第56条：影响评估内容与记录保存。

### 理想结论

该做法仍存在较高法律风险。公司已告知、取得书面同意、加密存储、限制访问、未向第三方共享，这些是有利合规因素；但仍存在三类核心缺口：其一，公司无法证明使用人脸识别具有必要性，仅以效率更高作为理由不足；其二，拒绝录入人脸的替代方案耗时较高，可能使员工同意不具备真实自愿性；其三，公司未进行个人信息保护影响评估。建议补做个人信息保护影响评估，论证必要性和比例性，提供刷卡、工牌、密码等真实可行替代方案，并留存评估和告知同意材料。

### 当前系统表现摘要

- 风险结论方向基本正确：识别到敏感个人信息处理风险、替代方案不合理风险、影响评估缺失。
- 证据链明显不足：Top-3 evidence 命中 GB/T 3.2、GB/T 10.2 和《网络安全法》第13条，未命中应优先出现的个保法第17、28、29、30、55、56条。
- 出现不理想表述：回答称“依据材料未包含《个人信息保护法》等具体法律条文”，实际更准确应表述为“本次检索证据链未召回相关个保法条文”。
- citation integrity 失败：`[《信息安全技术个人信息安全规范》3.2]` 与证据链 citation 格式不一致。

### 暂定失败归因

- 不是单纯缺 anchor；复杂事实没有被拆解成稳定法律争点。
- 检索层未能把 `人脸识别 + 员工 + 替代方案不可行 + 必要性 + 影响评估` 映射到个保法核心条文。
- Rerank top-3 偏向标准术语和不相关安全事件条款，导致答案只能在弱证据上生成。
- 输出层把“未召回”误说成“依据材料未包含”，需要后续输出约束或诊断提示。

### 后续建议

将该样本作为 v0.4.7.0 hidden eval / issue spotting 的第一条种子样本。下一步优先做离线诊断工具，而不是继续补 anchor：

```text
复杂事实 → 争点标签 → 期望法条 → 实际 evidence_chain → 缺口报告
```

目标是区分问题发生在：

- 争点识别失败；
- 争点到法条映射失败；
- 候选召回失败；
- rerank 排序失败；
- citation/output 约束失败。

## seed_002_employee_monitoring_software_complex

### 原始问题

```json
{
  "question": "某互联网公司为防止员工泄露商业机密，在员工办公电脑上安装了行为监测软件。该软件会记录员工的网页浏览记录、文件传输情况以及键盘操作日志。公司在员工入职手册中说明“公司可能对办公设备进行安全管理”，但未详细说明监测范围、保存期限和具体用途。员工若拒绝安装监测软件，则无法使用公司内部办公系统。请问该做法是否存在法律风险？",
  "k": 5
}
```

### 期望争点

- `employee_monitoring_notice_scope`：员工监测软件涉及网页浏览记录、文件传输、键盘日志等个人信息处理，应明确告知监测范围、目的、方式和保存期限。
- `necessity_and_minimization`：保护商业秘密具有正当目的，但监测范围应限于必要范围，不能以概括安全管理名义过度收集。
- `refusal_and_work_system_access`：拒绝安装即无法使用内部办公系统，可能使员工同意缺乏自愿性，也涉及是否以拒绝非必要处理为由拒绝基本工作条件。
- `commercial_secret_protection_balance`：商业秘密保护措施具有正当性，但不能替代个人信息处理合法性审查。
- `security_audit_boundary`：安全审计可作为管理措施，但需要明确审计边界、访问权限、留存期限和防滥用机制。

### 期望核心法条

- 《中华人民共和国个人信息保护法》第5条：合法、正当、必要和诚信原则。
- 《中华人民共和国个人信息保护法》第6条：处理个人信息应限于实现处理目的的最小范围。
- 《中华人民共和国个人信息保护法》第13条：个人信息处理合法性基础。
- 《中华人民共和国个人信息保护法》第14条：同意应在充分知情、自愿、明确的前提下作出。
- 《中华人民共和国个人信息保护法》第16条：不得因个人不同意处理其个人信息而拒绝提供产品或者服务，处理非必要个人信息除外。
- 《中华人民共和国个人信息保护法》第17条：处理个人信息前的告知义务。
- 《中华人民共和国个人信息保护法》第51条：个人信息处理者应采取相应安全技术措施和管理措施。
- 《中华人民共和国反不正当竞争法》第10条：商业秘密保护和保密措施正当性。

### 理想结论

该做法存在较高法律风险。公司为防止商业秘密泄露而对办公设备进行安全管理具有一定正当性，但现有告知过于概括，未明确监测范围、保存期限和具体用途；网页浏览记录、文件传输情况和键盘操作日志可能覆盖大量与安全目的无关的个人信息，存在过度收集和必要性不足风险。员工拒绝安装即无法使用内部办公系统，也可能影响同意的自愿性。建议公司重新评估监测必要性和比例性，细化告知内容，限定监测范围和保存期限，设置权限控制与审计机制，并提供与安全目的相称的替代管理方案。

### 当前系统表现摘要

- 风险结论方向部分正确：识别到告知不充分、强制同意、必要性不足和隐私风险。
- 证据链不足：Top-3 evidence 命中《网络安全法》第31条、《反不正当竞争法》第10条和 GB/T 11.7，未命中个保法第5、6、13、14、16、17、51条。
- 出现不理想表述：回答称“材料中未直接包含关于员工个人信息处理、知情同意、必要性原则等核心法律条文”，更准确应表述为“本次检索证据链未召回个保法核心条文”。
- 风险类型出现污染：输出包含“泄露国家秘密风险”“安全事件处置不当”“未履行通知义务”，与题目事实不匹配，疑似由安全/泄露类规则或相邻语义误触发。
- 置信度偏高：在核心个保法证据缺失、且风险类型污染明显的情况下，`confidence_score=0.85`、`needs_human_review=false` 不够保守。

### 暂定失败归因

- 复杂事实没有先拆解为“员工监控 + 个人信息处理 + 商业秘密保护边界 + 拒绝后果”的法律争点。
- 检索被“商业机密”“安全管理”“审计”吸引，偏向商业秘密条款和安全审计标准，未稳定召回个保法一般原则、告知和同意条款。
- 输出层在证据不足时仍生成较完整结论，并给出偏高置信度。
- 风险补全规则可能把“泄露/安全事件/国家秘密”类风险带入不匹配场景，需要后续诊断规则贡献来源。

### 后续建议

该样本应作为 hidden eval 的第二条复杂企业场景，重点验证：

```text
员工监控事实 → 争点标签 → 个保法核心条文 → 商业秘密保护条文 → 证据链缺口 → 风险类型污染
```

优先诊断而非补 anchor。目标是确认失败发生在：

- issue spotting 未抽取员工监控/必要性/告知争点；
- 争点到个保法条文映射不足；
- 候选召回有个保法但 rerank 未排进 top-3；
- risk supplement 误触发导致风险类型污染；
- 置信度和人工复核策略未能识别证据链不足。

## seed_003_algorithmic_price_discrimination_complex

### 原始问题

```json
{
  "question": "某电商平台为提升用户购物体验，使用算法对用户消费记录、浏览历史、搜索关键词和停留时间进行分析，并向不同用户展示不同价格和优惠力度的商品。平台在隐私政策中写明“可能基于用户行为进行个性化推荐”，但未明确说明会根据用户画像实施差异化定价，也未提供关闭个性化推荐的选项。部分用户发现，同一商品在不同账号上的价格存在明显差异。请问该做法是否存在法律风险？",
  "k": 5
}
```

### 期望争点

- `automated_decision_pricing`：平台利用个人信息进行自动化决策并影响交易价格、优惠力度等交易条件。
- `unreasonable_differential_treatment`：同一商品在不同账号价格差异明显，可能构成不合理差别待遇。
- `transparency_gap`：隐私政策仅概括写明个性化推荐，未明确说明差异化定价逻辑和影响。
- `reject_or_non_profiled_option_missing`：未提供关闭个性化推荐、非个性化展示或不针对个人特征的选项。
- `explanation_right`：用户有权要求平台解释个人信息处理规则或自动化决策相关规则。

### 期望核心法条

- 《中华人民共和国个人信息保护法》第24条：自动化决策透明度、公平公正、不得不合理差别待遇、提供不针对个人特征的选项或便捷拒绝方式。
- 《中华人民共和国个人信息保护法》第48条：个人有权要求个人信息处理者对其个人信息处理规则进行解释说明。
- 《中华人民共和国个人信息保护法》第17条：处理个人信息前应告知处理目的、处理方式、个人信息种类等事项。
- 《中华人民共和国个人信息保护法》第7条：处理个人信息应遵循公开、透明原则。

### 理想结论

该做法存在较高法律风险。平台基于用户消费记录、浏览历史、搜索关键词和停留时间等信息实施差异化定价，已经超出一般个性化推荐的风险边界，可能构成自动化决策下的不合理差别待遇。仅在隐私政策中概括说明“可能进行个性化推荐”，不足以覆盖基于用户画像实施价格差异的处理方式和影响；平台还应提供不针对个人特征的选项或便捷拒绝方式，并允许用户要求解释相关处理规则。建议停止不透明的差异化定价，补充自动化决策告知，提供关闭或非个性化选项，并开展算法公平性审查。

### 当前系统表现摘要

- 主结论较好：正确识别自动化决策、差异化定价、透明度不足、拒绝机制缺失和解释说明权。
- 核心证据较好：Top-1 命中个保法第24条，Top-2 命中个保法第48条，已经覆盖本题主干。
- 证据链仍有污染：Top-3 命中《民法典》第610条“标的物质量不符合要求”，与算法差异化定价无关。
- citation 绑定过宽：风险类型和整改动作都统一引用了个保法第24条、第48条和民法典第610条，导致无关条款被绑定到所有结论上。
- 输出重复：`recommended_actions` 中“提供解释说明和人工复核渠道”与“提供解释说明、拒绝自动化决策或人工复核申诉渠道”等内容重复；风险类型中“自动化决策违规风险/自动化决策不当”“差异化定价歧视风险/算法歧视”也存在语义重复。
- 可补证据：若能召回个保法第17条或第7条，隐私政策告知不足与公开透明原则会更稳。

### 暂定失败归因

- 不是主检索失败，而是 top-3 evidence 混入无关民法典条款，说明 rerank 或候选裁剪仍可能把高相似但低相关民商事条款带入证据链。
- 风险和动作引用没有按具体结论粒度绑定证据，而是把 evidence_chain 全量引用到每个结构化字段。
- 输出规则补全与 LLM 自然生成叠加，导致风险类型和整改动作出现重复。

### 后续建议

该样本可作为 hidden eval 中的“相对成功但仍需打磨”样本，用于验证：

```text
核心法条命中 → 无关证据污染 → 结构化字段去重 → citation 粒度绑定
```

后续优先诊断：

- 为什么民法典第610条进入 top-3；
- 是否需要 evidence relevance guard，而不是继续补 anchor；
- 风险类型和整改动作是否应做语义去重；
- 结构化字段 citation 是否应从“全量证据链”改为“字段级可支持证据”。

## seed_004_online_education_ai_participation_scoring

### 原始问题

```json
{
  "question": "某在线教育平台为了提高课堂互动效率，要求学生在上课期间开启摄像头，并通过AI系统自动分析学生的表情、视线方向和专注度，生成“课堂参与度评分”。平台在用户协议中提到“可能使用智能技术优化教学体验”，但未详细说明会对学生行为进行自动化分析，也未说明评分结果是否会影响课程评价或奖学金评定。部分学生认为系统误判较多，并担心长期保存视频数据。请问该做法是否存在法律风险？？",
  "k": 5
}
```

### 期望争点

- `camera_video_sensitive_info`：课堂视频、面部图像、表情和视线方向可能涉及人脸/生物识别信息或敏感个人信息。
- `student_context_and_minor_risk`：在线教育平台用户可能包含未成年人，需关注学生个人信息保护和更严格的同意/监护规则。
- `automated_decision_scoring`：AI 自动分析行为并生成课堂参与度评分，属于自动化分析、评估个人行为习惯或表现的活动。
- `significant_impact_uncertainty`：评分结果是否影响课程评价或奖学金评定未说明，若影响个人权益，应提供说明、拒绝或人工复核机制。
- `notice_specificity_gap`：用户协议仅写“可能使用智能技术优化教学体验”，未明确说明采集摄像头视频、表情视线分析、评分用途和保存期限。
- `retention_and_pipia`：长期保存视频数据和处理敏感个人信息，应明确保存期限并考虑个人信息保护影响评估。

### 期望核心法条

- 《中华人民共和国个人信息保护法》第17条：处理个人信息前的告知义务。
- 《中华人民共和国个人信息保护法》第24条：自动化决策透明度、公平公正、重大影响决定的说明和拒绝权。
- 《中华人民共和国个人信息保护法》第28条：敏感个人信息定义。
- 《中华人民共和国个人信息保护法》第29条：处理敏感个人信息应取得单独同意。
- 《中华人民共和国个人信息保护法》第30条：处理敏感个人信息还应告知必要性和对个人权益的影响。
- 《中华人民共和国个人信息保护法》第31条：处理不满十四周岁未成年人个人信息的专门规则和监护人同意。
- 《中华人民共和国个人信息保护法》第47条：保存期限届满或处理目的已实现后的删除义务。
- 《中华人民共和国个人信息保护法》第55条：处理敏感个人信息、利用个人信息进行自动化决策前的影响评估。
- 《中华人民共和国个人信息保护法》第56条：影响评估内容与记录保存。
- 《中华人民共和国个人信息保护法》第73条：自动化决策定义。

### 理想结论

- 《中华人民共和国个人信息保护法》第48条：个人有权要求个人信息处理者对处理规则进行解释说明。
- 《中华人民共和国个人信息保护法》第55条：自动化决策、敏感个人信息和出境前的个人信息保护影响评估。
- 《数据出境安全评估办法》第4条：应申报数据出境安全评估的情形。
- 《个人信息出境标准合同办法》第5条：出境前个人信息保护影响评估。
- 《中华人民共和国消费者权益保护法》相关退货退款、公平交易和知情权条款。

### 理想结论

该做法存在显著法律风险。平台基于历史订单、退货频率、聊天记录、设备指纹、支付账户等信息生成异常售后评分，并自动拒绝退款和限制促销权益，属于对消费者权益有重大影响的自动化决策。用户协议仅作概括性风险控制说明，不足以覆盖具体信息类型、自动化评分逻辑、境外总部参与、数据访问范围、保存期限和申诉方式。若境外总部可访问或维护模型涉及中国区用户数据，还需满足个人信息出境告知、单独同意和合规路径要求。建议平台补充明确告知，提供人工复核和申诉渠道，限制自动拒绝退款的适用条件，开展个人信息保护影响评估和出境合规评估，并审查黑名单模型公平性。

### 当前系统表现摘要

- 主结论方向很好：识别到告知不足、自动化决策、数据出境、人工复核缺失和消费者权益风险。
- 证据链部分相关但不完整：Top-2 命中《数据出境安全评估办法》第4条，Top-3 命中《个人信息出境标准合同办法》第5条，能支撑出境路径；但 Top-1 是 GB/T 10.1 安全事件应急处置，与本题主争点弱相关。
- 核心个保法义务缺失：未召回第17、24、28、29、30、38、39、48、55条，尤其缺自动化决策和重大影响决定条款。
- 消费者权益依据缺失：回答提到消费者权益侵害，但 evidence_chain 没有消费者权益保护法相关条文。
- citation 绑定过宽：所有风险类型和整改动作都绑定到 GB/T 10.1、出境评估办法第4条、标准合同办法第5条，无法支持自动化决策、消费者退款权益和人工复核结论。
- `confidence_score=0.9` 且 `needs_human_review=false` 偏高；核心自动化决策法条缺失时应触发降置信或人工复核。

### 暂定失败归因

- 系统能推理出正确的复合风险，但检索只抓住“跨境/出境”部分，未覆盖自动化决策和消费者权益两个核心维度。
- “风险/安全/风控”语义可能吸引 GB/T 安全事件条款进入 top-1，属于安全事件语义污染。
- 缺少 issue coverage scoring：一个复合场景至少需要覆盖出境、自动化决策、敏感/高风险个人信息、消费者权益四类证据。
- 结构化字段 citation 仍是全量证据链绑定，无法反映每个风险项的真实依据。

### 后续建议

该样本适合作为 hidden eval 中“跨境电商售后风控/消费者自动化决策”场景，用于验证：

```text
售后风控 → 自动拒绝退款 → 消费者权益 → 境外模型维护 → 高风险画像数据 → 人工复核
```

后续诊断重点：

- 能否同时召回个保法自动化决策条款和出境条款；
- 能否识别消费者权益争点并召回消费者权益保护法；
- 是否需要 domain routing 将“风控/安全”与“安全事件处置”区分开；
- confidence 是否应受 issue coverage 缺口约束；
- 是否需要对自动化决策重大影响场景强制检查人工复核/申诉证据。
