## 支持的辅助信号

- 主争点缺证据：原回答涉及的主要风险、责任后果或整改动作，最终 evidence_chain 没有保留对应的主要条文。
- 案由核心条文缺口：场景登记认为应覆盖的核心条文没有进入最终证据链，需要判断是 registry 范围偏宽还是 final evidence 漏选。
- 候选证据进入最终证据时流失：条文曾在候选、anchor 或 rerank input 阶段出现，但最终没有被选进 evidence_chain。
- 答案与证据链可能脱节：原 LLM 输出中的风险类型、整改动作或结论，未被现有 evidence_chain 直接托住。
- 定义条款替代规范条款复核：命中的条文可能偏定义性，缺少义务、责任、程序或后果条款，需要人工看是否足够。
- 基础检索或 anchor 依赖稳定性复核：基础检索、元数据、切分或 anchor 依赖信号提示：法律库扩大后召回稳定性可能不足。

- 原 LLM 主要整改动作：立即停止在未告知并取得单独同意的情况下收集精准定位信息用于广告推荐、向用户补充弹窗告知处理目的、方式、种类、保存期限等信息，并取得单独同意、如广告推荐未在原告知目的范围内，应重新告知并取得用户同意、对已收集的敏感个人信息进行合规性审查，必要时予以删除或匿名化处理、建立敏感个人信息处理专项合规机制，确保未来处理行为符合法定要求、补充告知并获取单独同意、停止非必要收集

需要重点看：
- 案由和原 LLM 输出是否在讨论同一个法律问题？
- 最终 evidence_chain 是否足以支撑原回答中的主要风险类型和整改动作？
- 被标记为缺失的主要条文，是否确实应当进入最终证据链？
- 曾被召回但没进入最终证据链的条文，是否应当被保留？
- 原回答中的风险后果、整改动作或结论，哪一项最缺少证据支撑？
- 当前证据是否只是定义条款，而缺少真正说明义务、责任、程序或后果的条款？
- AI 参考建议中的根因和后续动作是否过宽，是否需要人工收窄？
- 高风险 case 即使预筛有把握，也建议人工看一眼。
