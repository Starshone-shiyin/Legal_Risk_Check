# 法律风险智能审查系统：核心技术与实验报告素材（16 页建议版）

> 用途：本稿是比赛报告的“核心技术、实验与答辩”素材，不是正式法律意见书。内容仅陈述仓库中已实现或已有可复现记录支持的能力；尚未验证的项目均标注为“待补实验”。
>
> 适用范围：面向中文法律概念问答、企业合规风险分析和材料辅助审查的证据型 RAG 原型。系统输出用于信息检索与风险提示，不能替代律师、法务或监管机关的专业判断。

## 一、报告总叙事与展示原则

### 建议主线

法律问答的难点不只是“回答通顺”，而是：能否检到正确法源、能否把结论和证据一一对应、缺少依据时会不会主动降级、遇到法规更新或外部事实时能否受控补证。因此，本项目将生成模型置于证据链之后，并通过混合检索、法律概念增强、重排序、证据充分性门控（Evidence Sufficiency Gate, ESG）和受控联网检索形成可追溯的回答链路。

### 统一展示口径

- “证据命中”指预期法源是否进入前 `K` 条证据，不等同于法律结论正确，也不等同于模型准确率。
- “ESG 分数”是证据适足性与路由指标，不是答案正确率或风险概率。
- 联网结果是外部事实或法规线索，单独标记为 `web_result`；法律结论不应仅建立在网页摘要上。
- 所有正式实验使用冻结问题集、固定版本知识库、固定 `K`、固定运行配置，并保存输入文件哈希、原始 JSON 报告及判定报告。
- 评测集含 60 个内部构造的法律/合规问题，适合作为工程回归和消融对照；不能宣称代表真实世界全部法律问题或全国司法实践。

## 三、实验结果汇总表（可直接改制为图表）

### 3.1 单变量控制消融：60 个冻结案例、固定集合、固定 K

| 配置 | 组件 | Evidence Recall@K | MRR@K | nDCG@K | 多来源覆盖率 | P50 检索时延 | P95 检索时延 |
|---|---|---:|---:|---:|---:|---:|---:|
| C0 Dense | Dense | 0.075000 | 0.069444 | 0.056448 | 0.116667 | 1140.40 ms | 1288.89 ms |
| C1 + BM25 | C0 + 稀疏召回 | 0.075000 | 0.069444 | 0.056448 | 0.116667 | 1192.45 ms | 1401.65 ms |
| C2 + 扩展 | C1 + 概念扩展 | 0.083333 | 0.075000 | 0.061558 | 0.133333 | 1193.19 ms | 1464.06 ms |
| C3 + 概念锚点 | C2 + 概念法源锚点 | 0.112500 | 0.122222 | 0.107979 | 0.150000 | 1357.23 ms | 1646.06 ms |
| C4 + 场景锚点 | C3 + 场景锚点 | 0.970833 | 0.833333 | 0.872521 | 0.933333 | 1635.91 ms | 2518.33 ms |
| C5 + 规划 | C4 + 多问题规划 | 0.970833 | 0.833333 | 0.872521 | 0.933333 | 1535.83 ms | 2312.40 ms |
| C6 + 重排序 | C5 + Cross-Encoder | 0.987500 | 0.841667 | 0.883036 | 0.950000 | 1974.58 ms | 2645.22 ms |

**结果解读**：C0 至 C6 相邻配置只改变一个开关，控制变量裁判已通过。场景锚点（C3 -> C4）是本冻结集上的主要增益来源；复杂规划在全体题目上未显示独立增益；Cross-Encoder 带来边际排序改善并增加延迟。结果是预期法源排序结果，不能外推为法律问答准确率，也不能归因于单一模型。

### 3.2 三类扰动鲁棒性：24 个派生成对改写问题

| 配置 | 整体 Recall@K | 口语化 | 术语替换 | 多问题重组 |
|---|---:|---:|---:|---:|
| C0 Dense | 0.041667 | 0.000000 | 0.062500 | 0.062500 |
| C3 概念锚点 | 0.166667 | 0.000000 | 0.250000 | 0.250000 |
| C4 场景锚点 | 0.583333 | 0.375000 | 0.875000 | 0.500000 |
| C6 完整方案 | 0.750000 | 0.625000 | 0.875000 | 0.750000 |

每类包含 8 题，C0、C3、C4、C6 的对照分别隔离“纯 Dense”“概念锚点”“场景锚点”和“最终重排序方案”。结果表明，场景锚点对表达扰动保持关键作用，Cross-Encoder 进一步提升口语化和多问题重组情形的排序；术语替换下 C4 与 C6 持平。

**边界说明**：改写集由原始法源标注派生，题目由人工成对改写；它验证措辞变化下的检索稳定性，不是外部公开基准，不能写作“泛化准确率”。

### 3.3 ESG 正式路由：同一 60 个冻结案例的 C6 配置

| 指标 | 结果 | 正确表述 |
|---|---:|---|
| 平均 ESG | 0.938833 | 冻结集上的平均结构性证据充分性分数。 |
| 充分作答率 | 95% | 57/60 题路由为“带证据作答”。 |
| 联网补证率 | 5% | 3/60 题被路由至受控网页补证，网页不替代本地法源。 |
| 人工复核率 | 0% | 仅说明本冻结集未触发人工复核，不代表复杂事实永不需要复核。 |

**边界说明**：ESG 是证据治理和路由指标，不是置信概率、法律结论正确率或合规责任评分。

### 3.4 端到端闭环抽样：6 个跨领域问题

跨数据、反垄断、知识产权和民商事的 6 题抽样回归均通过内部工程断言（`6/6`）。断言覆盖预期法源、答案关键词、风险字段、建议动作和引用链。该组是系统集成回归，不是法律意见准确率或司法准确率评测。

## 五、正式提交前的补实验清单

这些项目是把本素材从“可答辩的工程原型”进一步提升为“实验更扎实的参赛报告”的优先工作，不应在完成前写成结果。

1. **ESG 扩展鲁棒性评测**：在现有 60 个冻结案例外，补充“法源缺失、实时法规、外部市场事实、恶意/无关检索”四类案例；报告 ESG 的充分作答率、补证率、复核率与误路由案例。
2. **人工标注的证据正确性评测**：由至少两名具法律基础的标注者独立判断“引用是否支持结论”“是否遗漏关键例外”，报告一致性与分歧处理规则。
3. **时效性问题评测**：设置带发布日期与采集时间的法规/监管/市场事实问题，对比本地检索、受控联网与人工查证；单独统计来源有效性，不能混入法条 Recall@K。
4. **锚点依赖消减实验**：从高依赖案例中构造同义改写、跨领域迁移和条号遮蔽测试，分别观察密集检索、混合检索、概念扩展和锚点的贡献。
5. **端到端人工可用性试验**：用真实但脱敏的企业合规案例，记录法务使用者查找法源、发现缺口、导出证据的时间和主观评分；实验前应完成伦理、隐私和授权处理。
6. **稳定性与性能复测**：固定硬件、模型、知识库快照与网络条件，分别报告冷启动/热启动、并发水平和代理开关下的 P50/P95/P99；当前报告只能展示已有单机链路记录。

## 六、答辩高频问题与建议回答

| 可能追问 | 建议回答 |
|---|---|
| 你们和直接调用大模型有什么区别？ | 系统不以“生成一段流畅回答”为完成条件，而以“是否取得可回溯证据、证据是否充分、是否需要补证或人工复核”为闭环。 |
| C4 为什么提升这么大，会不会是规则泄漏？ | C4 只在 C3 基础上新增场景锚点，控制变量裁判确认相邻配置仅改变一个开关。提升来自规则辅助的工程价值，而不是单一模型突然“懂法”；我们同时披露锚点依赖，并用人工改写集检查措辞变化下的稳定性。 |
| `59/60` 是否代表 98.3% 的法律正确率？ | 不是。它是内部冻结回归集上多项工程断言的通过结果；我们将检索命中、证据充分性和法律结论正确性严格区分。 |
| 联网后是否会带来不可信信息或提示注入？ | 网页结果与本地法源隔离，不自动入库；法律/监管检索限制官方来源优先，网页证据独立标注并要求人工复核，系统不执行页面脚本或页面指令。 |
| ESG 分数高是否就能自动给出法律意见？ | 不能。ESG 只说明选中证据的结构性适足度；复杂事实认定、证据真实性、法条适用例外与责任判断仍需专业人员复核。 |
| 为什么要保留人工复核？ | 法律风险审查需要责任边界。人工复核不是系统失败，而是系统在证据不足、时效性强或事实复杂时的正确升级路径。 |
