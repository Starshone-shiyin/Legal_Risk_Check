# 自定义 Skill 使用与高级扩展手册

## 1. 功能定位

“我的技能”用于把已经受控的 RAG 分析环节编排为可复用流程。它不是开放式 Agent，也不是脚本执行器：用户可选择节点、调整顺序、保存和运行流程；模型调用、知识库访问、联网检索、密钥和文件权限始终由服务端统一控制。

当前每个 Skill 最多包含 6 个节点，同一种节点最多使用一次，连线必须构成无环图。内置 Skill 是官方示例，只能运行，不能编辑或删除；自建 Skill 保存在 `data/user_skills.json`。

## 2. 内置 Skill

| 名称 | 适用场景 | 处理方式 |
| --- | --- | --- |
| 法律风险基础审查 | 一般法律、合规风险问答 | 本地检索 → 证据门控 → 风险分析 → 报告输出 |
| 现行法源补充核验 | 可能涉及新规、政策或本地库缺失的提问 | 本地检索 → 证据门控 → 受控联网补证 → 报告输出 |
| 证据充分性复核 | 想先确认知识库是否足以支撑结论 | 本地检索 → 证据门控 → 报告输出 |

内置模板会随应用升级自动恢复官方定义，以保证演示口径一致；此过程不会改动任何自建 Skill。

## 3. 现阶段如何自建

1. 进入“我的技能”，点击“新建技能”。
2. 填写一个能说明用途的名称和简短用途说明，例如“劳动合同条款初审”。
3. 从固定节点中勾选所需环节，并用上下按钮排列执行顺序。
4. 点击“校验流程”。只有节点参数、节点数和无环关系均通过校验时才保存。
5. 保存后在该 Skill 的运行区输入问题。输出会附带执行计划，便于说明该回答经过了哪些受控步骤。

推荐起点：

- 常规法务问答：本地检索 → 证据门控 → 风险分析 → 人工复核 → 报告输出。
- 合同材料审查：材料提取 → 本地检索 → 证据门控 → 风险分析 → 报告输出。
- 需要核验时效性：本地检索 → 证据门控 → 联网补证 → 人工复核 → 报告输出。

## 4. 固定节点的使用原则

| 节点 | 何时使用 | 关键边界 |
| --- | --- | --- |
| 材料提取 | 已上传并解析合同、制度或其他材料时 | 仅能选取已授权的解析材料，最多 3 份。|
| 本地检索 | 所有需要法源或知识库依据的回答 | 只召回证据，不直接生成结论。|
| 证据门控 | 需要控制“无依据回答”时 | 建议保留，并开启本地法源要求。|
| 联网补证 | 本地库缺失、法规更新或需核对公开事实时 | 采用服务端受控搜索；优先官方来源。|
| 风险分析 | 需要风险等级、原因和建议动作时 | 结论必须受已取得证据约束。|
| 人工复核 | 高风险、事实复杂或证据不足时 | 只标记复核需求，不替代人工决定。|
| 报告输出 | 所有面向用户的结果 | 建议开启引文，以便回溯证据。|

## 5. 高级自定义：第三层扩展方向

当前仅为“可视化编排”：用户只能组合平台批准的节点。

若需要拓展，则应由开发者在服务端新增经过审核的节点适配器，再将其注册给编排器。

建议按以下路径实施：

1. **定义扩展契约**：为每个新节点声明唯一 `node_type`、中文名称、用途、Pydantic 参数模型、输入/输出摘要和版本号。参数必须是有限枚举、范围值或结构化对象，拒绝任意脚本、任意 URL 和原始提示词覆盖。
2. **实现服务端适配器**：适配器只能调用应用已封装的能力，例如法规检索、合同解析、受控联网或市场数据服务；不得把 API Key、Qdrant 客户端、文件系统路径或模型客户端暴露给前端或 Skill 配置。
3. **接入注册表**：由管理员将适配器加入节点白名单和参数校验表，再通过 `/skills/node-types` 向前端发布。旧 Skill 若引用被下线节点，应以“不可运行、需迁移”处理，不得静默降级。
4. **设置治理关卡**：新节点至少经过单元测试、失败/超时测试、权限测试、提示注入测试和离线验收；涉及外网、个人信息、交易建议或高风险法律结论时，必须附人工复核节点与审计日志。
5. **灰度发布与版本迁移**：先以只读或模拟模式验证，再允许少量内部 Skill 使用；保留节点版本和运行元数据，使报告能追溯“用的是什么节点、什么参数、哪个版本”。

适合后续新增的受控节点包括：法规版本核验、裁判文书检索、合同条款比对、企业风险事件聚合、市场数据指标查询和报告导出。每一种都应是“平台实现、管理员审核、用户编排”，而不是让终端用户直接执行外部程序。
