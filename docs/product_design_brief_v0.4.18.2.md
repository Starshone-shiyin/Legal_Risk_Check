# 企业法律风控系统产品设计简报

## 1. 项目一句话

本项目希望建设一个 Harvey 风格的企业法律风控系统：以高质量法律 RAG 为核心，结合市场行情、供应链、监管变化、地缘政治和企业自身行为数据，帮助企业识别、解释、追踪和生成法律风险报告。

它不是一个普通聊天机器人，也不是单纯的行情看板，而是一个面向企业管理者、法务、合规、风控和投研人员的综合风险工作台。

## 2. 当前项目基础

项目当前已经具备较扎实的法律 RAG 内核：

- 已入库 15 份法规/标准，覆盖数据合规、公司治理、市场竞争、知识产权、财税、民商事、安全合规等领域。
- RAG 主链路可以完成法律问题检索、证据链生成、风险等级判断、整改建议和报告输出。
- 最近 full RAG eval 为 `59/60`，检索阶段 `PASS=60`。
- 已有 evidence alignment、evidence coverage、legal functional typing、ingestion quality、Qdrant integrity、project health check 等质量治理工具。
- 已有离线人工复核工作台雏形，但它是内部审阅工具，不是最终产品 UI。

设计重点不需要从“模型是否能答”开始，而应从“企业用户如何理解风险、审阅证据、推进处置”开始。

## 3. 目标用户

主要用户：

- 企业法务
- 合规负责人
- 风控负责人
- 董秘/公司治理相关人员
- 投资、并购、出海、供应链管理人员
- 需要做企业尽调或风险报告的专业服务人员

用户特点：

- 不一定懂技术。
- 需要快速知道“哪里有风险、为什么有风险、证据是什么、下一步做什么”。
- 对可追溯性、引用依据、报告质量和专业可信度非常敏感。
- 不希望看到过于花哨或营销化的页面，更需要清晰、克制、专业、高信息密度的工具界面。

## 4. 产品整体结构

建议将系统拆成五个主要模块：

1. 首页 / 风险驾驶舱
2. 市场行情与外部风险
3. 供应链地图与区域风险
4. 法律风控 RAG 工作台
5. 企业全生命周期风险概览

这些模块应共享同一套视觉语言：浅色、专业、克制、清晰、有金融/法律/风控系统的质感。

## 5. 首页 / 风险驾驶舱

首页不是宣传页，而是用户进入系统后的风险总览。

建议展示：

- 企业综合风险等级或风险指数
- 今日/本周新增风险
- 高优先级预警
- 法律风控待处理事项
- 外部市场/政策/地缘风险摘要
- 供应链高风险节点
- 最近生成的风险报告
- 数据源状态，例如法规库、行情源、供应链数据、企业文件、RAG 状态

设计目标：

- 一眼看出当前企业风险状态。
- 能快速跳转到具体风险来源。
- 不要做成营销 landing page。
- 不要大面积装饰性渐变和空洞 hero。

## 6. 市场行情与外部风险

该模块可以参考行情系统，但目的不是炒股或纯行情展示，而是识别外部风险信号。

可能包含：

- 行业指数
- 企业相关上市公司或供应商行情
- 汇率、利率、大宗商品
- 监管政策变化
- 舆情或新闻事件
- 地缘政治事件
- 事件对企业经营、合同履行、供应链、合规义务的影响解释

设计重点：

- 不要像交易软件一样堆满 K 线。
- 应该更像“外部风险雷达”。
- 行情数据应能转译成风险语言：影响方向、影响环节、风险等级、建议关注事项。

## 7. 供应链地图与区域风险

该模块建议使用浅色地图 UI，可以有中国地图和世界地图两种视角。

地图对象：

- 供应商
- 客户
- 工厂
- 仓库
- 物流节点
- 国家/地区/省份
- 产业集群

风险信息：

- 地缘政治风险
- 出口管制/制裁风险
- 关税和贸易限制
- 物流中断
- 地方监管风险
- 数据跨境风险
- 替代供应商状态

设计重点：

- 地图应简洁、浅色、专业。
- 节点颜色表达风险等级。
- 连线表达供应关系或业务流。
- 点击节点后展示风险摘要、证据来源、建议动作。
- 不建议一开始做复杂 3D 地球，先做清晰可读的二维地图更可靠。

## 8. 法律风控 RAG 工作台

这是当前项目最成熟的能力，应作为核心工作区。

建议布局：

- 左侧：项目/会话/报告历史
- 中间：类似 ChatGPT 的法律风控问答区
- 右侧：证据链、引用法条、风险标签、整改建议、置信度、人工复核提示

支持能力：

- 输入法律或风控问题
- 上传合同、制度、尽调材料、公告、财报等文件
- 输出风险结论
- 展示 evidence chain
- 展示引用法规和条文
- 生成结构化风险报告
- 支持人工复核和导出

设计重点：

- 不能只是聊天气泡。
- 必须突出“证据链”和“可复核依据”。
- 用户要能分清：模型结论、法律依据、风险等级、整改动作、人工复核建议。
- 对非技术用户，应避免暴露过多内部字段名。

## 9. 企业全生命周期风险概览

该模块可以做成类似流程图或生命周期地图，帮助用户理解企业从设立到退出的风险全景。

建议节点：

- 企业设立
- 股权结构
- 融资与投资
- 劳动用工
- 数据合规
- 知识产权
- 合同交易
- 供应链管理
- 市场竞争
- 财税合规
- 出海与跨境
- 危机事件
- 并购/重组/退出/清算

每个节点展示：

- 当前风险等级
- 触发因素
- 相关法规
- 证据来源
- 建议动作
- 是否已生成报告
- 是否需要人工复核

设计目标：

- 让用户用“企业经营流程”理解风险，而不是只看零散 case。
- 适合做成管理层汇报视图。
- 可以作为首页风险摘要和法律 RAG 工作台之间的桥梁。

## 10. 视觉风格建议

整体风格：

- 专业
- 克制
- 可信
- 浅色
- 信息密度适中
- 法律、金融、企业风控气质

可以参考的感觉：

- 企业级 SaaS
- 金融风控系统
- 专业研究终端
- 法律科技工作台

应避免：

- 过度营销化 landing page
- 大面积深色赛博风
- 过多渐变球、装饰光斑、无意义插画
- 只有卡片堆叠，没有工作流
- 图标和标签过度抽象，导致非技术用户看不懂

## 11. 设计交付建议

第一阶段建议先设计以下页面：

1. 首页风险驾驶舱
2. 法律风控 RAG 工作台
3. 企业生命周期风险概览
4. 供应链地图占位页面
5. 市场外部风险占位页面

第一阶段不要求所有真实数据都接入，但页面需要体现：

- 信息架构
- 导航关系
- 模块优先级
- 风险等级表达方式
- 证据链展示方式
- 报告生成入口
- 人工复核入口

## 12. 当前设计重点问题

请设计专员重点思考：

- 如何让非技术用户一眼理解“风险来自哪里”？
- 如何把法律依据、证据链、模型结论三者区分清楚？
- 如何在首页展示综合风险，但不显得像普通 BI 看板？
- 供应链地图如何表达风险，而不是只展示地理位置？
- 法律 RAG 工作台如何既像 ChatGPT 一样易用，又比普通聊天更专业可信？
- 企业生命周期流程图如何成为“风险导航”，而不是静态说明图？

## 13. 暂不要求设计的内容

当前不要求：

- 完整商业官网
- 复杂品牌宣传页
- 真实行情接口细节
- 真实地图数据接入
- 完整权限系统
- 全量后端 API 定稿
- 移动端完整适配

当前最重要的是先确定产品骨架、核心页面和专业视觉方向。

## 14. 一句话设计目标

把这个系统设计成一个企业法务和风控人员愿意每天打开的专业工作台：能看总览、能查风险、能追证据、能生成报告，也能解释企业从设立到经营、供应链、出海和退出全过程中的法律风险。
